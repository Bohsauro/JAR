JAR

Just another router.

It sits between your apps and OpenRouter and sends every request to the cheapest provider that is actually up. Prices are worked out on your real token mix, slow or flaky providers are skipped, and if a call fails the next one in line answers.

One model, many prices.

The same model id is hosted by a dozen providers, and what they charge can differ by an order of magnitude. List prices also mislead: if most of your tokens are cache reads, a provider that is cheap on input can still be the most expensive one for you. JAR compares providers on what your traffic would cost.

How it picks, every few minutes.

No benchmarks and no guesswork. JAR reads pricing, throughput and uptime for every provider of the models on your watchlist, then makes the same three moves each time.

1

Price it your way

Every model and provider pair gets one number: dollars per million tokens, weighted by your input, cache and output split.

2

Drop what's broken

Providers under your throughput or uptime floor are skipped. So are the ones that hit a budget you set, by requests, tokens or spend.

3

Route and fall back

Requests go to the cheapest provider left. If it errors, the next candidate answers and the client never notices.

Chains decide what to try first.

A chain is an ordered list of steps. JAR walks it top to bottom and uses the first step that has a healthy provider.

  • Free first, then paid. Try every :free model before spending anything.
  • Pin a provider on any step when you need a specific host.
  • Keep several chains and call one by name with penny:<chain>.

data/chains.json

// free models first, then a pinned model, then the cheapest paid one
{
  "name": "main",
  "primary": true,
  "entries": [
    { "type": "cheapest", "filter": ":free" },
    { "type": "model", "model": "deepseek/deepseek-chat-v3" },
    { "type": "cheapest" }
  ]
}

Anything that speaks OpenAI works.

JAR exposes a standard /v1/chat/completions endpoint with its own API keys and streaming. Change the base URL and keep your code.

openai SDKbase_url LangChainChatOpenAI Cursor, Aidercustom endpoint curlX-API-Key header

python

from openai import OpenAI

client = OpenAI(base_url="http://your-host:8490/v1",
                api_key="pnk-…")

r = client.chat.completions.create(
    model="penny",  # your primary chain
    messages=[{"role": "user", "content": "hello"}],
)
print(r.model)  # the model that actually answered
